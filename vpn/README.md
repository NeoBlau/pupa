# Hysteria 2 на своём сервере

Скрипт `hysteria2.sh` ставит сервер Hysteria 2 на чистую Ubuntu 22.04/24.04 и выдаёт
готовые конфиги клиентов: ссылку `hy2://`, QR-код в терминале и YAML-файл.

## Сначала — что это вообще такое

Hysteria 2 — не «VPN» в смысле WireGuard, который поднимает сетевой интерфейс.
Это прокси поверх QUIC (UDP). Трафик маскируется под HTTP/3 к обычному сайту,
а скорость держится даже на рваных каналах с потерями — ради этого протокол и делали.

На устройстве весь трафик заворачивает уже клиентское приложение своим TUN-режимом.
Сервер про это ничего не знает, поэтому никаких `ip forward` и NAT-правил тут нет.

## Установка

Скопируй скрипт на сервер и запусти от root. Один из двух вариантов:

### Вариант А — есть домен (так лучше)

```bash
curl -fsSLO https://raw.githubusercontent.com/NeoBlau/pupa/claude/vpn-server-setup-meszeh/vpn/hysteria2.sh
chmod +x hysteria2.sh
sudo ./hysteria2.sh install --domain vpn.example.com --email me@example.com
```

Домен должен A-записью указывать на IP сервера, а TCP/80 — быть свободен: там
Let's Encrypt проверяет владение. Дальше сертификат настоящий, клиенту не нужен
режим `insecure`, и со стороны всё выглядит как честный HTTPS-сайт.

### Вариант Б — домена нет

```bash
sudo ./hysteria2.sh install
```

Сгенерится самоподписанный сертификат с SNI `www.bing.com`, а клиент будет
проверять его по отпечатку (`pinSHA256`) вместо цепочки CA. Работает сразу,
но при глубоком анализе связка «левый IP + самоподписанный серт» заметнее.

### Флаги

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--domain D` | включает ACME и Let's Encrypt | нет, self-signed |
| `--email E` | почта для ACME | `admin@<домен>` |
| `--sni HOST` | имя в самоподписанном сертификате | `www.bing.com` |
| `--port N` | UDP-порт сервера | `443` |
| `--ip ADDR` | внешний IP вручную, если автоопределение врёт | автоопределение |
| `--masquerade URL` | какой сайт показывать случайному посетителю | `https://www.bing.com/` |
| `--client NAME` | имя первого клиента | `incy` |
| `--no-obfs` | выключить обфускацию salamander | включена |
| `--no-bbr` | не трогать congestion control | включает BBR |

## Про обфускацию

По умолчанию включён `salamander` — он ломает узнаваемый QUIC-отпечаток, по которому
Hysteria вычисляется пассивным DPI. Цена: трафик перестаёт выглядеть как HTTP/3 и
становится просто шумным UDP-потоком.

Выбирай так:
- провайдер режет или душит соединение через пару минут → оставляй salamander;
- всё летает и без него, хочется максимальной незаметности «под обычный сайт» →
  `--no-obfs` вместе с `--domain`.

Клиент обязан знать тот же пароль обфускации — он уже зашит в выданную ссылку и YAML.

## Управление

```bash
sudo ./hysteria2.sh list            # кто есть
sudo ./hysteria2.sh add phone       # добавить клиента, сразу покажет QR
sudo ./hysteria2.sh show incy       # ссылка, QR и YAML существующего
sudo ./hysteria2.sh key             # только ссылка одной строкой
sudo ./hysteria2.sh del phone       # отозвать доступ
sudo ./hysteria2.sh status          # жив ли сервис
sudo ./hysteria2.sh uninstall       # снести всё
```

У каждого клиента свой логин и пароль, так что удаление одного не трогает остальных.
Последнего удалить нельзя — Hysteria не стартует с пустым списком пользователей.

## Куда всё кладётся

| Путь | Что |
|---|---|
| `/etc/hysteria/config.yaml` | конфиг сервера (перезаписывается при `add`/`del`) |
| `/etc/hysteria/users.tsv` | список клиентов, `имя<TAB>пароль` |
| `/etc/hysteria/setup.env` | параметры установки, из них собирается конфиг |
| `/root/hysteria-clients/` | `.yaml`, `.txt` и `.png` каждого клиента, права 600 |

Руками править `config.yaml` смысла нет — следующий `add` затрёт. Меняй `setup.env`,
потом любой `add`/`del` пересоберёт конфиг.

## Подключение клиента

### Откуда берётся ключ

Ключ — это строка вида `hy2://...`. Её не надо нигде покупать и ни у кого
просить: её генерит твой сервер в момент установки. INCY — только клиент,
внутри него серверов нет, и пока скрипт не отработал, ключа не существует.

Скрипт печатает ключ сам, в конце `install` и после каждого `add`. Если
терминал уже закрыт — достать можно в любой момент:

```bash
sudo ./hysteria2.sh key             # первый клиент, голая ссылка
sudo ./hysteria2.sh key noutbuk     # конкретный клиент
sudo ./hysteria2.sh show incy       # то же самое плюс QR и YAML
```

Либо просто прочитать файл: `cat /root/hysteria-clients/incy.txt`.

Ключ у каждого клиента свой. Нужен доступ ещё одному человеку или устройству —
не копируй существующий, а сделай `sudo ./hysteria2.sh add имя`: тогда доступ
можно будет отозвать по отдельности.

### INCY

INCY понимает обе схемы — `hy2://` и `hysteria2://` — и все параметры, которые
генерит скрипт: `sni`, `insecure`, `pinSHA256`, `obfs`, `obfs-password`.
Так что ссылка из скрипта вставляется как есть, ничего переписывать не надо.

**С телефона.** После `install` (или `add`) в терминале рисуется QR-код —
открой в INCY добавление конфига и наведи камеру. Всё.

**С компьютера.** Скопируй ссылку и добавь её в INCY из буфера обмена:

```bash
sudo ./hysteria2.sh show incy
```

Первой строкой будет `hy2://...` — это она.

Если добавлял конфиг вручную и что-то не сходится, сверься с
[описанием параметров share-ссылок в документации INCY](https://incy.gitbook.io/docs/dokumentaciya-dlya-razrabotchikov/parametry-konfigov).

INCY умеет ещё и port hopping (`server:443,8443-8445` в ссылке) — трафик прыгает
по диапазону портов, что помогает против шейпинга по порту. Скрипт этого не
настраивает: на сервере нужны отдельные правила iptables, которые заворачивают
весь диапазон на рабочий порт. Если упрёшься в шейпинг — скажи, допишу.

### Остальные клиенты

Три формата на выбор, любой hy2-клиент понимает хотя бы один:

1. **QR-код** — печатается в терминале после установки, плюс лежит картинкой
   в `/root/hysteria-clients/<имя>.png`.
2. **Ссылка `hy2://...`** — импорт из буфера обмена. Лежит в `<имя>.txt`.
3. **YAML** — для клиентов, которые не едят ссылки. Лежит в `<имя>.yaml`,
   вывести на экран: `sudo ./hysteria2.sh show <имя>`.

Забрать файлы на свою машину:

```bash
scp root@СЕРВЕР:/root/hysteria-clients/incy.png .
```

## Если не подключается

Порядок проверки — сверху вниз, почти всегда ломается на первых двух:

```bash
sudo ./hysteria2.sh status                      # сервис вообще запущен?
sudo journalctl -u hysteria-server -n 50        # что он пишет
sudo ss -lnup | grep hysteria                   # слушает ли UDP-порт
```

- **Сервис не стартует, в логах ACME** — домен не резолвится на этот IP либо TCP/80
  занят (чаще всего nginx). Останови его и перезапусти сервис.
- **Сервис жив, клиент молчит** — фаервол хостера. У Hetzner, Oracle, AWS, GCP есть
  свой сетевой фильтр помимо `ufw`, и UDP там закрыт по умолчанию. Открой UDP/443
  в панели провайдера.
- **Коннектится и сразу рвётся** — вероятно DPI. Переставь с другим портом и
  обфускацией: `sudo ./hysteria2.sh uninstall && sudo ./hysteria2.sh install --port 8443`.
- **Ошибка сертификата в self-signed режиме** — клиент проигнорировал `insecure`/`pinSHA256`
  из ссылки. В INCY проверь, что оба параметра доехали в настройки конфига; в других
  клиентах возьми YAML, там они прописаны явно.

## Безопасность

- Пароли клиентов генерятся из `/dev/urandom`, по 24 символа на клиента.
- `config.yaml`, `users.tsv`, `setup.env` и папка с клиентами — права `600`/`700`, только root.
- Файлы из `/root/hysteria-clients/` — это готовый доступ к серверу. Передавай их
  так же, как передавал бы пароль, и не оставляй в общих чатах и облаках.
